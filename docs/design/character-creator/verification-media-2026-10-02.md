## Проверка в браузере и через API

Использован встроенный браузер Codex, фактическая ширина 1280 px.
Мобильная компоновка в этом этапе повторно не проверена: override viewport
не изменял фактическую ширину документа. Общая сетка страницы не менялась;
добавлена необязательная иконка рядом с названием навыка.

Созданы две явно технические публичные карточки, не канонические герои:

| Карточка | ID | Файлы |
| --- | --- | --- |
| Проверка портрета — 02.10.2026 | `6afc2e6a-fcf3-4d02-af10-8c2f61d7a787` | Портрет PNG 550×819, 886 200 байт; иконка PNG 328×328, 119 327 байт |
| Проверка сжатия — 02.10.2026 | `f7f3ce00-d82f-47b6-9a8d-729a0d7e1180` | Портрет JPEG 1073×1600, 272 152 байта; иконка PNG 328×328, 119 327 байт |

Первый сценарий выявил избыточный PNG-вес непрозрачного портрета; после исправления
вторая карточка создана полностью с опубликованного Yandex frontend.
Исходный портрет — утверждённый `lambert.webp`, иконка — `fighter-v1.png`.
WebP-исходник сам по себе меньше итогового JPEG; оптимизация сравнивает JPEG
с прежним PNG-перекодированием, а не обещает уменьшить любой исходный файл.

Проверено:

- Семь шагов, сохранение анкеты с портретом и активным навыком, переход на карточку.
- При сравнении двух портретов сохраняется выбранный вариант, второй остаётся
  только в памяти конструктора. Иконка связана с правильным активным навыком.
- Перезагрузка опубликованной карточки восстанавливает оба изображения;
  список показывает портрет, старые карточки без изображения — общую заглушку.
- На карточке JPEG-портрет выводится целиком, прозрачная PNG-иконка без подложки
  файла; скриншот проверен визуально. Ширина документа равна ширине окна, 1280 px.
- В консоли опубликованной карточки нет ошибок и предупреждений.
- Оба файла возвращают 200, правильный MIME,
  `Cache-Control: public, max-age=31536000, immutable` и SHA-256 ETag.
  `If-None-Match` возвращает 304. Неизвестный UUID — 404.
- Анкета без файлов сохраняет JSON-совместимость; Base64 не используется.

Канонические JSON, существующие герои и книга не менялись.

## Ограничения

Все сохранённые карточки и их медиа публичны через API; входа и редактирования нет.
Object Storage и PostgreSQL не имеют общей транзакции: при сбое после загрузки
могут остаться непривязанные объекты. API их не выдаёт. Обслуживание, лимиты
и модель затрат описаны в [character-media.md](../../architecture/character-media.md).
Советник AI Studio остаётся следующим этапом.
