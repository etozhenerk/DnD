# Советник конструктора персонажей

## Первый шаг: бесплатные подсказки

Добавлены общий каталог [`shared/advisor/guide.json`](../../shared/advisor/guide.json),
характер советника в [`persona.md`](../../shared/advisor/persona.md) и публичный
`GET /creator/advisor`. Чтение не создаёт сессию, не сохраняет анкету и не вызывает AI.
Каталог загружается при старте Go API из `ADVISOR_GUIDE_PATH`; Docker и CI включают файл.
API возвращает политику бюджета и фактические возможности, с кэшем процесса на пять минут.

Фронт использует тот же каталог из сборки: переход на этап не ждёт сеть.
Светлое облачко с одной короткой фразой появляется над советником с хвостиком к его голове. Реплика доступна
как `status` для экранного диктора, внутри нет кнопок. Облачко и персонаж стоят
последовательно; короткий текст не перекрывает кнопки. Reduced motion отключает
анимацию появления и приветствия.

Советник — находчивый пернатый сообщник, который обращается на «ты», иногда шутит
и помогает выбрать. Он не запрещает необычные имена и не навязывает билд.
Каталог и инструкция не добавляют новых персонажей или фактов в канон мира.

## Место для диалога

Под советником находится кнопка «Поговорить с советником». Она открывает
большое модальное окно: история занимает отдельную область с прокруткой,
поле сообщения и отправка находятся снизу. Окно закрывается крестиком,
Escape или кликом вне него; фокус возвращается на кнопку. Фоновая страница
недоступна для взаимодействия, пока открыт диалог. История общая для всего
процесса создания и не очищается при закрытии окна.

На десктопе лента семи этапов занимает общую строку над формой и Советником.
Правая колонка имеет естественную высоту; под чатом расположены четыре коротких
поручения, которые открывают диалог и подставляют редактируемый текст. Подписи этапов
контрастные, без тёмной прямоугольной подложки. Убраны отдельное затемнение
вокруг портрета и нижний декоративный кант. Мобильное взаимодействие отложено
по решению пользователя: плавающий
советник и нижняя панель не включаются; отдельную компоновку будем проектировать позже.

Ввод и отправка включаются по `capabilities.chat` из API. Облачный диалог включён
2 октября 2026 года. При выключенном runtime виден статус подготовки.
Первая версия приветствия использовала исходный арт и CSS.
После одобрения опубликованы кадровые состояния, описанные ниже.

## Архитектура и следующие возможности

- Одна роль советника с режимами диалога, короткого комментария и предложения
  заполнить поля. Генерация изображений — отдельный инструмент этой роли.
- Инициативный комментарий — только реплика в облачке. Его текст попадёт в
  историю чата, чтобы игрок мог продолжить тему. Не показывать устаревший ответ
  после смены имени, класса или этапа; не запускать LLM на каждую клавишу.
- Сессия советника отделена от анкеты и будущего авторизованного черновика.
  Непредсказуемый токен хранится в памяти текущего конструктора; в БД — хэш,
  срок действия, история диалога и журнал расходов. Анкета остаётся в памяти
  фронта, её текущий снимок передаётся как контекст запроса, без автосохранения.
- Сначала модель получает только публичный лор и серверные каталоги правил.
  Ответ не меняет поля автоматически. Для заполнения нужен структурированный
  результат, проверка баланса сервером и просмотр игроком перед применением.
- Лимит **200 ₽ на сессию создания** включает сообщения, автоматические
  комментарии, изображения и повторы. Сервер уже ограничивает диалог;
  все инструменты используют этот же журнал.
- Перед платным запросом резервировать его максимальную стоимость транзакцией
  в PostgreSQL; после ответа учитывать фактическое usage. Повтор с тем же
  request ID не создаёт второй вызов. Неясный исход по таймауту сохраняет резерв.
  Дополнительно нужны общий месячный предел и ограничения частоты: без входа
  лимит сессии нельзя надёжно превратить в лимит на человека.
- Режим создания по фотографии исключён из текущего плана по решению пользователя.
  Обычная генерация портрета и иконок по тексту входит в обновление ниже.

Существующие `/drafts/*` по-прежнему закрыты до авторизации. Сессия беседы
не является черновиком и не предоставляет права редактировать персонажа.

## Реализованный второй шаг: диалог и журнал расходов

Этот раздел фиксирует первую опубликованную версию. Новые режимы и инструменты
описаны в разделе «Полный Советник» ниже; фактическая приёмка указана в конце документа.

Код опубликован и чат включён 2 октября 2026 года после явного разрешения пользователя.
Миграции 000006/000007 применены; runtime получил `ai.languageModels.user` на каталог
проекта. Общий бюджет **10 000 ₽/мес** утверждён пользователем.

### HTTP и интерфейс

Три отдельные операции: начать сессию, прочитать её и отправить сообщение.
[Контракт 0.8](../../shared/api/openapi.yaml) задаёт обязательные поля и ошибки.
История живёт в PostgreSQL, а её секрет — в памяти конструктора. Закрытие модального
окна не сбрасывает беседу; выход из конструктора очищает frontend-кэш сессии.
Перезагрузка страницы теряет секрет. Новая сессия не объявляет игрока владельцем героя.

TanStack Query читает историю с отменой и без автоматического повторения ошибок.
Пока ход `reserved`, клиент проверяет его каждые 2 секунды. После неопределённой
отправки сохраняются её UUID и тело: повтор возможен только явно с тем же ID.
Поле очищается сразу при отправке, неизменяемая попытка хранится отдельно. Enter отправляет, Shift+Enter переносит строку.
Поле остаётся в фокусе во время отправки. История прокручивается за ответом, пока
игрок не начал читать выше; повторное открытие не проигрывает старую печать заново.

Ответ появляется плавной анимацией на клиенте после получения целого JSON.
Это **не поток токенов провайдера**: время ожидания обозначается компактной репликой.
Reduced motion отключает печать. Поддержаны абзацы, заголовки, списки, жирный текст
и inline code; HTML, ссылки и изображения остаются текстом, не исполняются.

### Контекст и агент

Первая роль советника реализована на бэкенде поверх Chat Completions. Объект агента
в Agent Atelier пока не создаётся; управление инструментами и генерация изображений
появятся следующим этапом. Инструкция Советника находится в `shared/advisor/persona.md`.

Публичные знания загружаются из канона при старте: каталог классов, рас и навыков;
дубли готовых пресетов `defaultStats` и описаний `playStyle` исключены, основы классов сохранены;
из мировой карты передаются только ID, названия, подписи, описания земель и публичный
анонс `teaser.description`. Другие поля карты и файлы кампаний исключены явной проекцией.
Имя, выбранные раса/класс, этап и краткая задумка текущей анкеты передаются на один вызов.
Анкета в SQL не сохраняется. Текст сообщения и ответ хранятся как приватная беседа.
Модель видит до шести последних завершённых ходов в пределах 32 КиБ текста prompt;
её инструкция прямо сообщает о неполной истории. Сводку памяти и поиск по публичному
лору добавим отдельно. Числа в совете не заменяют серверную проверку готовой анкеты.

### SQL, лимиты и исходы

- `advisor_sessions`: хэш секрета, 24-часовой срок доступа, учтённая сумма.
- `advisor_turns`: текст реплики/ответа, хэш запроса, модель, reservation, usage,
  стоимость и исход `reserved` / `succeeded` / `uncertain`.
- `advisor_months`: общий расход и административная блокировка месяца.

Деньги — integer в миллионных долях рубля. Месяц считается в `Europe/Moscow`.
Резерв привязывается к месяцу начала запроса и не переносится при ответе в следующем.
SQL-блокировки и уникальный индекс сериализуют бюджеты и активный ход; транзакция
завершается до сетевого вызова AI, поэтому соединение БД не удерживается во время генерации.
Общее поступление ходов сериализуется также на границе месяца. Повтор UUID со старым
телом читает результат, с другим телом возвращает 409, новые ход и расход не создаются.

Принятые ограничения первой версии: 200 ₽/сессия, 10 000 ₽/месяц, 100 ходов/сессию,
один активный ход на сессию, шесть на сервис, 60 ходов/мин; новые сессии — 12/мин,
60 за последние 24 часа. Запросы истории и бесплатные подсказки LLM не вызывают.
Runtime-конкурентность установлена на 12 HTTP-запросов, чтобы чтения помещались рядом
с шестью генерациями; CPU/RAM и число подготовленных экземпляров сохраняются.

Цены закреплены вместе с `deepseek-v4-flash`: 0,3 ₽/1000 входных, 0,075 ₽/1000 кешированных,
0,5 ₽/1000 выходных токенов, включая НДС ([тариф](https://aistudio.yandex.ru/ru/docs/ai-studio/pricing),
проверен 02.10.2026). Рассуждения входят в `completion_tokens`; повторно не прибавляются.
`max_completion_tokens=4096` ограничивает видимый ответ и рассуждения
([API](https://aistudio.yandex.ru/en/docs/ai-studio/api/Chat-Completions/createChatCompletion)).

Резерв **31,8464 ₽** использует консервативную оценку входа: три токена на каждый
UTF-8 байт разрешённого текста плюс 1024 служебных токена и полный лимит выхода.
После получения корректного usage лишнее освобождается. Это резервная оценка;
живая проверка подтвердила параметры и usage для одной короткой реплики, но не
доказывает предел для всех возможных входов. При несовместимости возвращаем
выключенное состояние. Стоимость в журнале
считается по закреплённым ценам и usage, её сверяем с облачным биллингом при смене тарифа.

При обрыве, таймауте или невозможности подтвердить usage резерв не освобождается.
Миграция 000009 разрешает новый ход после `uncertain`, сохраняя прежний резерв.
Только `reserved` блокирует текущую сессию. После трёх минут оставшаяся попытка
показывается как `uncertain` и при новой отправке фиксируется в этом состоянии:
контейнер живёт максимум 120 секунд, прежний worker уже не может генерировать.
Повтор её UUID читает исход, а не вызывает провайдера. При нарушении оценённого token envelope блокируется весь месяц.
Автоматического повторения модели, возврата неизвестного расхода и фонового worker нет.
Учёт завершается синхронно с отдельным трёхсекундным cleanup даже при уходе браузера.

24 часа — срок доступа, **не срок удаления данных**. Автоматическая очистка истории
и сверка неизвестных исходов пока не реализованы; эти административные операции
нужно добавить до длительного публичного использования.

## Полный Советник: характер, скорость и предзаполнение

Обновление после первой облачной приёмки. До публикации возможности проверялись
локальным UI-примером. CI и облачная проверка выполняются через штатный журнал
расходов; фактические результаты фиксируются в отчёте публикации.

- Публичное имя в интерфейсе — «Советник». Голос задаёт обновлённая persona:
  обычно 2–4 предложения до 70 слов, без формальных заголовков и длинных лекций.
- Chat Completions запрашивает `reasoning_effort=low`; диалог и заполнение ограничены
  4096 выходными токенами вместе с рассуждениями, короткий комментарий — 384.
  Это настройка ускорения, не обещание фиксированного времени ответа.
  [Управление рассуждениями](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/generation/chain-of-thought).
- Каталог сокращён до описаний классов/рас и профилей навыков. Числовые основы
  выбранного класса добавляются отдельно. Общие итоги всех трёх завершённых
  кампаний доступны всегда; сюжетные абзацы публичной летописи добавляются по теме
  текущего запроса и двух последних реплик. Вход ограничен прежними 32 КиБ.
- Явно разрешены только `completedChronicle.completedSummary`, `finalResult`,
  `story`, ID и заголовок Нор’Иль’Скальда, Линда Смолл и Пенисуэлы.
  Мастерские сценарии, альтернативные финалы и исполняемые сценические bundle
  не входят в prompt. Это опубликованные итоги, не история конкретной комнаты.
- Модалка использует тот же кадровый Советник, что и страница. 30 сгенерированных
  кадров различают дыхание/моргание, размышление, речь, жест крылом, ошибку,
  однократные реакции наведения и клика. Ветка неподвижна, хвост проходит за ней.
  Приветствие и применение наброска запускают жест крылом один раз. Скрытая
  вкладка и reduced motion останавливают движение. Детали ассета и приёмки —
  [кадровая анимация](../design/character-creator/advisor-animation/README.md).
  Печать короткого ответа занимает не больше двух секунд; настоящий поток
  провайдера пока не добавлен.
- Рубли скрыты из UI; `meter` показывает процент оставшегося запаса сессии.
  Серверные денежные лимиты и консервативный резерв сохраняются.

### Режимы и предложение анкеты

Контракт 0.10 добавляет `chat`, `comment`, `suggest`, `fill`, `portrait`, `icon`
к отправке сообщения. `suggest` требует раздел, `icon` — ID существующего навыка.
`context.formData` — ограниченный снимок шести разделов, максимум 12 КиБ.
Длинные описания сокращаются до отправки; при заполненном prompt второстепенный
снимок опускается, исходная реплика игрока сохраняется. Снимок не сохраняется в SQL.

Модель предлагает имя, местоимения, внешность, историю, мотив, черты, расу,
класс, профили/названия навыков и описательное снаряжение. Сервер добавляет
утверждённые характеристики класса, стабильные ID предметов/навыков и базовую
атаку; полную анкету проверяет `creator.Catalog.Validate`. При сохранении класса
валидное ручное распределение игрока сохраняется. Модель не задаёт собственные
цены, заряды, HP/AC или произвольную механику. Невалидный ответ не попадает
в предложение; оплаченная генерация учитывается и автоматически не повторяется.

`proposal.formData` хранится в `advisor_turns.reply` как внутренний envelope
`advisor-proposal-v1:`. При чтении он разворачивается в обычную реплику и проверенный
набросок. `proposal.target` ограничивает применение одним разделом; выбор класса
заменяет класс вместе с его основой характеристик. Полный набросок заменяет все
поля, а сохранённые локальные медиа остаются. Перед применением игрок видит значения.
Отмена восстанавливает поля, пока игрок не изменил их после применения.
Иллюстрации остаются отдельными вариантами. Персонаж создаётся только обычным
сохранением итоговой анкеты после подтверждения этапов и серверной проверки.

### Инициативные реплики

Бесплатная подсказка этапа показывается сразу. После имени, расы или класса
платный комментарий ждёт 1,8 с без изменений, соблюдает паузу 30 с и максимум
шесть разных выборов за сессию. При открытом чате или активной операции
новый комментарий не отправляется. Ответ ограничен 160 символами, не меняет
поля и остаётся в истории; устаревшая реплика не заменяет актуальное облачко.
На сервере лимит шести комментариев проверяется независимо от браузера.

### Портреты и иконки

Используется отдельный инструмент Alice AI ART 3.0. Перед рисованием отдельный вызов DeepSeek составляет структурированный визуальный
промпт: subject, details, scene. В него поступают пожелания игрока и текущая анкета,
включая выбранный навык. Сервер добавляет обязательный фотореалистичный стиль,
композицию полного роста и ограничивает каждую часть так, чтобы итог для Alice
составлял не больше 500 символов. Фотографии, история чата и секреты мастера не передаются.
Синхронный Images API принимает `model`, `prompt`, `size`; неподдерживаемые
параметры формата и streaming не отправляются.
[Официальный API](https://aistudio.yandex.ru/ru/docs/ai-studio/api/Images/createImage).

Стоимость закреплена в коде: 2,23 ₽ за успешную генерацию, включая НДС.
[Тариф](https://aistudio.yandex.ru/ru/docs/ai-studio/pricing).
Подготовка промпта оплачивается по токенам DeepSeek отдельно от 2,23 ₽ за картинку.
Оба этапа входят в один UUID и общий журнал сессии/месяца. До начала резервируются
16 КиБ входа и 1024 выходных токена компоновщика плюс цена изображения;
после успеха остаются только фактические токены и стоимость картинки.
При некорректном JSON компоновщика генератор не вызывается, учитывается только текст.
Повтор UUID возвращает прежний результат. Если генератор уже ответил, но подготовка
или сохранение файла не удалось, стоимость всё равно учитывается. Неопределённый
исход удерживает резерв. Автоматических повторов платного вызова нет.

Изображения сохраняются в существующем закрытом бакете под `advisor/`:
портрет до 1 МиБ, иконка до 128 КиБ и 512 px. Сохраняются пропорции и весь кадр;
фон не вырезается. Приватный `GET /advisor/sessions/{id}/images/{requestId}`
проверяет Bearer-токен и срок сессии, отдаёт бинарный JPEG/PNG с `no-store`.
Base64, публичных URL и ключей хранилища в ответах конструктора нет.
До восьми попыток изображения на сессию; до двух активных изображений во всём
сервисе, внутри общего предела шести генераций; до 128 изображений за скользящие
24 часа, чтобы ограничить объём временного хранилища. Готовый файл применяет игрок:
портрет попадает в галерею, иконка привязывается к существующему навыку.

«Герой с портретом и иконками» последовательно создаёт проверенный набросок,
один портрет и иконки его активных навыков. Между шагами можно остановиться.
Результаты остаются в чате; закрытие окна сохраняет набор и прекращает последующие
шаги после текущего вызова. Применение набора — отдельное действие игрока.
Сохранение героя использует прежний multipart pipeline и переносит выбранные
файлы в постоянные `characters/` объекты. Генерация по фото исключена.

### Публикация и приёмка

Миграция `000008_advisor_tools` применена (режим, цель и дескриптор результата
в `advisor_turns`), роль `ai.imageGeneration.user` выдана runtime на каталог проекта.
В GitHub Actions включён `DND_ADVISOR_IMAGES_ENABLED`.
Новых SQL-прав и публичного доступа к бакету нет.
Время выполнения контейнера увеличено с 30 до 120 с для изображения.
Штатный timeout API Gateway достаточен, его настройки не меняются.

Для временных `advisor/` результатов настроено удаление через два дня
средствами Object Storage. До изменения у бакета не было lifecycle rules;
добавлено только правило `advisor-temporary-results`. К `characters/` оно
не относится. Lifecycle проверяется ежедневно,
поэтому удаление не обещает точность до часа.
[Lifecycle](https://yandex.cloud/ru/docs/storage/operations/buckets/lifecycles).

Браузером проверены применение/отмена отдельного поля, полный набор с медиа,
привязка иконки и возвращение в чат на локальных ответах API без платных запросов.
Тесты доступа, повторов, тарифа, лимитов, строгого JSON и подготовки файлов
прошли в CI; локальные сборки и тесты не выполнялись.
[Порядок публикации](character-advisor-release.md) и
[визуальная проверка](../design/character-creator/verification-advisor-update-2026-10-02.md).

### Исправление диалога и инструменты из реплики

Обычная реплика может вызвать `propose_character`: модель возвращает аргументы
анкеты, сервер проверяет их тем же валидатором, что и режим `fill`, а игрок получает
карточку наброска с просмотром и применением. Текстовое обещание не заменяет результат.
`generate_character_image` возвращает проверенное поручение `action`: UUID вычисляется
детерминированно от UUID исходной реплики. Клиент выполняет отдельный `portrait/icon`
только из обработчика отправки; чтение истории и открытие модалки ничего не генерируют.
Повторное выполнение читает существующий результат, общий журнал и квоты сохраняются.
Явные команды «нарисуй портрет» и «сгенерируй иконку» сразу идут в этот pipeline;
неоднозначные поручения остаются в обычном чате с инструментами.
Служебный prompt делегированного рисунка не выводится как реплика игрока.
Раздел предложения определяется активным этапом, выпадающий список удалён.
Изображение героя запрашивается в полный рост, с ногами и обувью целиком в кадре.
[Инструменты Chat Completions](https://aistudio.yandex.ru/ru/docs/ai-studio/api/Chat-Completions/createChatCompletion).

Схемы инструментов занимают до 4 КиБ и вычитаются из прежнего лимита 32 КиБ prompt.
Полная анкета и обычный диалог допускают 60 секунд генерации и 70 секунд сценария;
комментарий остаётся на 22/26 секундах. Клиент ждёт 75 секунд, рисунок — 115.
Ошибка одной попытки больше не запрещает продолжать разговор или рисовать в этой сессии.
Кнопка «Получить ответ из диалога» появляется только при неизвестной/активной отправке
и читает журнал; для завершённой ошибки бессмысленная проверка больше не предлагается.
