# Интерфейс кампании

Реализовать визуальное представление опубликованной кампании. Игровой движок и мастерскую консоль оставлять специализированным скиллам.

## Подготовка

Прочитать `AGENTS.md`, утверждённый `implementation-plan.md`, канонический campaign JSON, manifest и существующую FSD-структуру. Проверить существующие `entities`, `widgets`, `features` и страницы до создания новых компонентов.

## Реализация

1. Хранить маршрут и композицию в `app` и `pages`, данные и бизнес-логику — в нижних слоях.
2. Читать факты только из `content/` и разрешать арты существующим resolver.
3. Делать один компонент на `.tsx` и локальный `Component.module.css` рядом.
4. Использовать только переменные из `shared/styles/variables.css` для цветов, градиентов и теней.
5. Сохранить тёмный сказочный язык, доступные подписи, клавиатуру и `focus-visible`.
6. Поддержать публичную сцену, арты и варианты состояния без раскрытия будущих сцен и секретов мастера.
7. Не возвращать удалённые dashboard-паттерны и не добавлять UI-библиотеку без необходимости.
   Видимые сюжетные двери и проходы должны работать по клику на объект через общий SceneHotspotLayer с hover/focus-visible-подсветкой, включая проверки доступа и применение необходимого умения. Не оставлять такой клик только в короне. Для новых зон передавать background, чтобы координаты следовали изображению при cover/contain, и проверять 1024/1280 px.
8. Любую легенду или художественную вводную выводить через общий `SceneTextPanel`; локальные варианты `legendPanel` запрещены.
   Для описания игровой сцены использовать `appearance="narration"` и `readAloud`: фиксированный заголовок «Рассказчик», ниже только описание. Заголовком управляет общий компонент; не передавать имя NPC, не добавлять название сцены, акт, действия или собственную разметку описания через `children`. Реплики допускаются внутри текста рассказчика.
9. Любую внебоевую проверку собирать через общий `SceneCheckPanel`, который переиспользует модальное окно `SceneDecisionModal`; не встраивать форму броска в панель мастера и не дублировать UI или состояние броска внутри adventure-компонента.
10. Не показывать в кнопке, открывающей проверку, характеристику, DC или последствие провала. Для всего окна `SceneDecisionModal` использовать проектный `--font-display` и максимум два явных кегля.

## Проверка

Запустить `npm run typecheck` и `npm run build`. Передать интерактивную проверку `$verify-dnd-campaign-release`; не запускать standalone Playwright автоматически.

## Результат

Показать изменённые FSD-слои, переиспользованные компоненты, маршруты и оставшуюся работу игрового движка.
