# Монеты удачи — 20 сентября 2026

## Результат и канон

- Подтверждённая натуральная 20 на внебоевой проверке даёт группе одну золотую монету. Одна монета позволяет перебросить одну внебоевую проверку, после чего тратится. Получение и расход разыгрываются за столом.
- Дополнительная монета выдаётся в начале приключения у Алексиса за принятую работу над нарядом: «Отлично» или «Достаточно», по существующему `alexis-style-stabilized`. По уточнению автора бонус перенесён с Оливии; её консультация монет не даёт.
- Новых предметов, событий, счётчиков, флагов, зарядов или ключей localStorage для монет нет. Автоматический успех, итог 20 с модификатором, боевые проверки и спасброски не награждаются.
- Отдельный арт создан встроенным `image_gen` и утверждён ответом «Да, вставляй». Канонический PNG 1254 × 1254: `assets/concepts/campaigns/penisuela/ui/luck-coin.png`. Растр скопирован без изменений. [Полный промпт](../luck-coin-image-prompt.md). Предмет Ламберта не изменён.

## Реализация

Канон: `rules.core.criticalCheckReward` и необязательный `manualCheckReward` в gameplay. Схема описана в `content/README.md`; рабочий gameplay и сценарий мастера синхронизированы с JSON и guide.

Слой entities описывает данные награды. Слой features наблюдает новые подтверждённые записи существующего журнала; уведомление отложено до завершения React updater и работает даже при недоступном хранилище. Начальная история — только исходная точка наблюдения. Очередь находится в `CampaignPresentation` выше границ сцен. Бой определяется на момент события, поэтому крит вне боя, который сам запускает бой, награждается, а броски внутри боя — нет. Запись в сохранение сама по себе наград не создаёт.

`ManualCheckRewardDialog` переиспользует `SceneDecisionModal`. Окно ждёт окончания общего эффекта критического броска, показывает арт, причину награды, правило и кнопку. У общего окна добавлен слой награды над прежними окнами выдачи предметов. Кнопка получает фокус; Tab сохраняет его внутри окна, Enter и Escape закрывают текущую награду, фокус возвращается. Есть reduced-motion и ограничение высоты.

## Встроенный браузер

Проверка выполнена через встроенный браузер Codex, без standalone Playwright. Для воспроизводимой чистой сессии использован отдельный локальный адрес `http://127.0.0.1:49237`; обычные локальные адреса содержали старые прохождения, в том числе незавершённый бой, поэтому не использовались для финальной проверки внебоевой награды.

- Pussy Sultan → «Заслужить доверие» → ввод 20 → «Узнать исход»: сначала виден общий эффект «Критическая удача», затем модальное окно монеты с новым PNG и описанием. До подтверждения окна награды нет.
- Enter закрывает окно; перезагрузка не повторяет монету. Консоль браузера без ошибок.
- Размеры 1024 × 768, 1280 × 720, 390 × 844: `scrollWidth === clientWidth`, окно полностью внутри viewport, изображение загружено (naturalWidth 1254), кнопка доступна. Проверены скриншоты средствами встроенного браузера; они показаны в задаче. Tab оставляет фокус на кнопке.
- Алексис → манекен → выбор трёх вещей → сдача наряда → «Принять наряд: достаточно»: показана бонусная монета с текстом благодарности Алексиса. Escape закрывает только монету; прежняя награда из двух разрешений в бар остаётся открытой, фокус переходит на «Продолжить».

Проверялся изменённый сценарий и общий механизм уведомлений. Полное ручное прохождение всей кампании, незатронутых страниц и героев заново не выполнялось. Пять героев сохраняют прежние характеристики и боевой баланс; ручные перебросы не автоматизированы и не включены в симуляцию боя. Commit, push и deployment не выполнялись.
