# ИИ-мастер: функции, модели и бюджет Yandex Cloud

Исследование от 25 сентября 2026 года. Общий предел — **18 000 ₽/30 дней** на React, Go, PostgreSQL, LLM, распознавание и синтез речи для шести участников. Облако пока не развёрнуто. «Бесплатная модель» означает веса без платы за лицензию, но аренда GPU и речь оплачиваются. Лицензию проверяем для конкретного репозитория.

## Какие задачи отдаём ИИ

| Задача | Роль ИИ | Что проверяет сервер |
| --- | --- | --- |
| Описания сцен и речь NPC | Ведёт повествование по активной сцене и утверждённому лору | Выдаёт только нужный контекст, отделяет публичное от секретного, не сохраняет выдуманный канон. |
| Разговоры и импровизация | Отвечает пяти героям, предлагает варианты развития | Сохраняет характеры, имена, местоимения и ограничения сюжета. |
| Враги | Выбирает действие и цель из переданного списка легальных вариантов | Проверяет ход, цель, способность и ресурсы; применяет результат в движке. |
| Проверки и бой | Озвучивает исход и его художественное описание | Броски, AC/DC, урон, HP, заряды, инициатива и раунды считает только движок по [домашним правилам](../content/rules.json). |
| Сюжетные последствия | Предлагает реакцию мира и следующий шаг | Граф, флаги и неоднозначные эффекты проверяет код; уникальный эффект подтверждает человек. |
| Журнал и летопись | Создаёт черновой пересказ по событиям | Сессионное состояние в БД и добавочный журнал; публикацию утверждает человек. |
| Голос | LLM получает текст STT, а её ответ отправляется в TTS | SpeechKit выполняет распознавание и озвучку; один аудиоответ раздаётся всем. |

Оркестратор даёт модели короткую карточку активной сцены, релевантные записи лора, состояние пяти героев, допустимые действия и резюме сессии. Ответ структурирован: `narration`, `npc_reply`, `proposed_action`, `target_id`. Шесть клиентов используют **один экземпляр** модели и очередь событий. Снимок и журнал позволяют продолжить игру после сбоя. Локальный `model-dnd-game-session` применён для проектирования снимков, событий, исправлений и разделения секретного/публичного состояния. Это дополнение к [этапу 7](roadmap/stage-7-game-sessions.md), где пока задан человек-мастер и летопись без ИИ; до реализации продуктовый контракт потребуется обновить. Новых фактов мира нет.

## Топ моделей в бюджете

Это **очередь тестирования для русскоязычной D&D-партии**, не доказанный рейтинг интеллекта. Одинакового D&D-бенчмарка нет. Размеры репозиториев служат фильтром: runtime, KV-кэш, tensor parallelism и задержка пока не измерены на Yandex A100. В MoE активна часть параметров на токен, но хранить в памяти требуется все веса.

| Приоритет | Официальный чекпойнт | Зачем тестировать | Ресурсы/риск |
| --- | --- | --- | --- |
| **1 — основной пилот** | [Qwen3.8-27B](https://huggingface.co/Qwen/Qwen3.8-27B), Apache 2.0, 27B dense, [55,6 ГБ](https://huggingface.co/Qwen/Qwen3.8-27B/tree/main) | Свежая крупная Qwen с [официальным примером vLLM](https://huggingface.co/Qwen/Qwen3.8-27B); испытать русский диалог и tool use. | **1 × A100 80 ГБ**, 150 ГБ SSD; оригинальные BF16 веса входят по объёму. Стартовый контекст 16–32 тыс. токенов требует проверки. |

Запуск TP=2, FP8 на A100 и задержка **не подтверждены**; [официальный пример](https://huggingface.co/Qwen/Qwen3.5-122B-A10B-FP8) использует 8 GPU. |
| **3** | [GLM-4.7-Flash](https://huggingface.co/zai-org/GLM-4.7-Flash), MIT, MoE 30B/3B active, [62,5 ГБ](https://huggingface.co/zai-org/GLM-4.7-Flash/tree/main) | Сравнить импровизацию, речь и скорость с Qwen. | **1 × A100 по весам**; официальный пример использует 4 GPU, запуск на одной надо проверить. |

| **5** | [DeepSeek-R1-Distill-Qwen-32B](https://huggingface.co/deepseek-ai/DeepSeek-R1-Distill-Qwen-32B/tree/main), MIT, [65,5 ГБ](https://huggingface.co/deepseek-ai/DeepSeek-R1-Distill-Qwen-32B/tree/main) | Контрольный тест тактики и рассуждения. Это дистиллят, не полный DeepSeek. | **1 × A100 по весам**; меньше запаса VRAM, чем у Qwen 27B. |

Запасной вариант — [Qwen3.6-27B](https://huggingface.co/Qwen/Qwen3.6-27B), если свежая 3.8 не заработает. [GPT-OSS-120B](https://developers.openai.com/api/docs/models/gpt-oss-120b) под Apache 2.0 официально заявлена для одной **H100** 80 ГБ; это не подтверждает запуск на A100, поэтому в оплаченный пилот её не закладываем. Порядок 2–5 может измениться после одинакового теста сцен.

## Смета на 30 дней по согласованной архитектуре

Используем [этап 3](roadmap/stage-3-backend.md): React в **Object Storage** за **API Gateway**, Go в **Serverless Containers**, **Managed PostgreSQL** как рабочую БД; отдельная GPU-ВМ только на время игры; SpeechKit для голоса. GitHub Pages после переноса не используется. В отличие от старого пилотного расчёта в [предыдущем плане](llm-gm-yandex-cloud-plan.md), фронт, бэк и БД здесь рассчитаны для уже согласованных облачных сервисов.

Допущения: регион Россия, цены с НДС, 720 часов; один хост PostgreSQL `c3-c2-m4` (2 vCPU, 4 ГБ) и 20 ГБ network SSD; до 20 ГБ статики, 100 тыс. запросов API Gateway и 100 ГБ исходящего трафика. На Go предусмотрено до ~20 часов оплаченного исполнения контейнера 1 vCPU/1 ГБ; фактическое время выполнения запросов может быть меньше. Оценочные **300 ₽** распределены между фронтом (50), Go (200), IP и операциями (50). Браузер отправляет короткую реплику по кнопке; Go вызывает STT, затем LLM и TTS. Для непрерывного потока шести микрофонов это другой бюджет. [Тариф Compute](https://github.com/yandex-cloud/docs/blob/master/md-docs/compute/pricing.md), [GPU-конфигурации](https://yandex.cloud/ru/docs/compute/concepts/gpus), [тариф PostgreSQL](https://github.com/yandex-cloud/docs/blob/master/md-docs/managed-postgresql/pricing.md), [классы БД](https://yandex.cloud/ru/docs/managed-postgresql/concepts/instance-types), [API Gateway](https://yandex.cloud/ru/docs/api-gateway/pricing), [Object Storage](https://yandex.cloud/ru/docs/storage/pricing), [Serverless Containers](https://yandex.cloud/ru/docs/serverless-containers/pricing), [SpeechKit](https://aistudio.yandex.ru/ru/docs/speechkit/pricing).

| Статья | 1 × A100, 18 ч | 2 × A100, 8 ч |
| --- | ---: | ---: |
| Фронт: Object Storage + API Gateway | до 50 ₽ | до 50 ₽ |
| Бэк: Go Serverless Containers | до 200 ₽ | до 200 ₽ |
| БД: хост `c3-c2-m4`, 720 × (2×1,8792 + 4×0,5072) | 4 167 ₽ | 4 167 ₽ |
| БД: SSD 20 ГБ × 720 × 0,0365 | 526 ₽ | 526 ₽ |
| Нейросеть: A100 + обязательные vCPU/RAM | 18 × 472,37 = 8 503 ₽ | 8 × 944,74 = 7 558 ₽ |
| Нейросеть: SSD, оплачивается и при остановке | 150 ГБ × 720 × 0,0199 = 2 149 ₽ | 250 ГБ × 720 × 0,0199 = 3 582 ₽ |
| Распознавание и озвучка SpeechKit | 1 000 ₽ | 1 000 ₽ |
| Временный IP GPU и прочие операции: резерв | 50 ₽ | 50 ₽ |
| **Итого, округлено по строкам** | **16 645 ₽** | **17 133 ₽** |
| **Остаток до 18 000 ₽** | **1 355 ₽** | **867 ₽** |

1 A100: `408,12 + 28×0,9882 + 119×0,3074 ≈ 472,37 ₽/ч`; две карты стоят вдвое больше. **18 и 8 часов включают подготовку, скачивание, пробные запуски и партии.** Четыре вечера по три часа на одной карте — около **13 810 ₽/месяц**; на двух — около **20 911 ₽**, за пределом бюджета. При выключенной GPU-ВМ CPU/GPU compute не тарифицируется, но SSD продолжает оплачиваться. Бюджетные уведомления сами ресурсы не останавливают. [Тарификация ВМ и дисков](https://yandex.cloud/ru/docs/compute/pricing), [бюджеты](https://yandex.cloud/ru/docs/billing/operations/budgets).

Резерв 1 000 ₽ для речи — условие push-to-talk: 20 часов **суммарно отправленного аудио** × 0,1626 ₽ за начатые 15 секунд ≈ 780 ₽ STT; 100 тыс. символов TTS v3 при плотной упаковке до 250 символов ≈ 65 ₽. Шесть непрерывных микрофонов по 20 часов каждый — около 4 683 ₽ **только STT**. Короткие фрагменты округляются вверх. [Тарифы SpeechKit](https://aistudio.yandex.ru/ru/docs/speechkit/pricing).

Один хост PostgreSQL — точка отказа. Это пилот, не отказоустойчивая конфигурация. Если к голосу понадобятся постоянные WebSocket-соединения или видео, смету и схему Go придётся изменить. Фактические цены и доступность GPU проверяем в калькуляторе непосредственно перед созданием ресурсов.

## Порядок развёртывания

1. Получить квоту на 1/2 A100 `gpu-standard-v3`, проверить наличие в `ru-central1-a/b`; стартовая квота может быть нулевой. [GPU](https://yandex.cloud/ru/docs/compute/concepts/gpus).
2. Создать каталог, VPC, группы безопасности и бюджетные уведомления. GPU API доступен только Go по внутреннему адресу; ключей SpeechKit в браузере нет. [Создание GPU-ВМ](https://yandex.cloud/ru/docs/compute/operations/vm-create/create-vm-with-gpu).
3. По этапу 3 развернуть React в Object Storage/API Gateway, Go в Serverless Containers, импортировать данные в PostgreSQL. Проверить один HTTPS origin, SPA fallback и разграничение публичных/мастерских DTO.
4. Создать GPU-ВМ с SSD 150 ГБ и рекомендованным CUDA-образом, проверить `nvidia-smi`, установить совместимый vLLM, скачать официальный Qwen3.8-27B с **зафиксированным commit SHA** через `hf download`. [Образы GPU](https://yandex.cloud/ru/docs/compute/concepts/gpus), [HF CLI](https://huggingface.co/docs/huggingface_hub/main/package_reference/cli).
5. Запустить vLLM с начальным контекстом 16–32 тыс., измерить VRAM, задержку первого токена, скорость, русский ответ и структурированное действие. Затем на той же ВМ сравнить GLM и дистиллят DeepSeek; 122B и Kimi-Linear пробовать только на 2 A100 отдельными конфигурациями. [Qwen](https://huggingface.co/Qwen/Qwen3.8-27B), [vLLM](https://docs.vllm.ai/en/latest/getting_started/installation/gpu/).
6. Собрать цепочку «голос → STT → LLM → текст и TTS», очередь реплик, лимиты, журнал и восстановление. Прогнать одинаковые 10–20 сцен, включая бой против пяти героев, секреты и одновременные шесть браузеров. Выбрать модель по качеству **и** реальной задержке.
7. Включать GPU перед партией и останавливать сразу после неё; сохранять события и краткое резюме, сверять реальный счёт. При выключенной GPU карта, герои и журнал доступны, ИИ-мастер временно недоступен. [Остановка ВМ](https://yandex.cloud/ru/docs/compute/operations/vm-control/vm-stop-and-start).

Открытые проверки: GPU-квота, совместимость свежей Qwen3.8 и двухкарточных MoE с A100, скорость на реальных сценах и фактический расход речи. Смета — расчёт по опубликованным тарифам, не выставленный счёт.
