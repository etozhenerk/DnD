# Хроники Восьми Земель

Кликабельный фронтенд для проведения авторских D&D-кампаний на одном общем экране. Мастер открывает сервис, показывает игрокам карту и ведёт приключение без регистрации, комнат и отдельного мастерского интерфейса.

## Что уже работает

- мировая карта из семи кликабельных сюжетных регионов, объединяющих восемь земель;
- отдельная страница героев с книжными разворотами;
- энциклопедия 11 канонических рас: семи игровых и четырёх встреченных в летописях;
- перелистывание легенды, характеристик и навыков персонажа;
- завершённая кампания Нор’Иль’Скальда с пересказом сюжета;
- завершённая кампания Вьетимы и острова Линда Смолл;
- release candidate кампании «Мальчишник конца света»: 40 публичных экранов, 16 исполняемых story scenes, 7 встреч, консоль мастера и три эпилога; production-runtime тесты проходят, полная браузерная приёмка ещё не закрыта;
- страницы-заготовки для будущих кампаний;
- броски `d4`, `d6`, `d8`, `d10`, `d12` и `d20`;
- адаптивная вёрстка без авторизации;
- отдельный список персонажей конструктора из Go API и чтение их карточек;
- конструктор всех семи этапов: образ, раса, класс, характеристики, навыки, снаряжение и итог; финальная кнопка отправляет целую анкету в Go API и открывает сохранённую карточку. До входа незавершённая анкета живёт только в памяти. Несколько вариантов портрета и иконки навыков пока доступны для локального предпросмотра; облачные медиа и советник подключаются отдельно.

В конструкторе используются локальные Cormorant Garamond и Alegreya; файлы шрифтов и SIL OFL-лицензии находятся в `src/shared/assets/fonts/`. Его визуальная концепция и текущие отличия от макетов описаны в [документе дизайна](../docs/design/character-creator/README.md).

## Локальный запуск

Требуется Node.js 22.12 или новее в пределах 22-й LTS-ветки.

Команды ниже выполняются из каталога `frontend/`:

```bash
npm ci
npm run dev
```

Локальный адрес: `http://127.0.0.1:4173/`. Раздел персонажей: `http://127.0.0.1:4173/characters`.

### API конструктора

HTTP-контракт находится в `../shared/api/openapi.yaml`, клиент и его TypeScript-модели — только в `src/`. Production использует опубликованный API Gateway. Локальные запросы идут через Vite proxy `/api`, поэтому отдельный CORS-доступ для localhost не требуется. Список и карточки читаются из той же облачной базы.

Для другого API задайте `VITE_API_BASE_URL` в локальном `.env.local` или окружении сборки. У прямого адреса API должен быть разрешён origin фронтенда; `.env.local` не коммитится.

До авторизации черновиков нет. Конструктор открывается без HTTP-запроса записи; состояние формы находится в React внутри открытого конструктора. Перезагрузка, закрытие вкладки или выход из конструктора сбрасывают незавершённую форму. Нет сохранения в `localStorage`/`sessionStorage`, серверного автосохранения, восстановления или обмена состоянием между вкладками. Старые токены анонимных черновиков не читаются. API закрывает `/drafts` до подключения входа и проверки владельца. Сохранение готового персонажа целиком подключается отдельно.

### Загрузка и кэш чтения

Один `QueryClient` живёт в памяти вкладки: каталог свежий 10 минут, страницы списка — 30 секунд, карточка — 2 минуты. Каталог сохраняется 30 минут после последнего использования, остальные запросы — 15 минут. Ключ карточки содержит ID, ключ списка — offset и limit. Одновременные одинаковые запросы объединяются; наведение, фокус и касание карточки запускают предварительную загрузку. Повторное открытие использует свежие данные сразу; обновление устаревших данных не убирает уже показанный интерфейс. Автоматических повторов ошибок и обновления по фокусу окна нет.

Кэш не сохраняется на диск и не содержит анкету конструктора. Первое чтение показывает скелетон, совпадающий с раскладкой списка или страницы; общий переход между маршрутами использует небольшой индикатор. Страницы персонажей и смена этапов имеют мягкое появление; браузеры без View Transitions используют CSS-анимации. При `prefers-reduced-motion` анимации отключены. Переход между этапами сохраняет состояние формы, смена страницы начинает прокрутку сверху.

Общий список и чтение доступны без входа; вкладки «Мои» и редактирования готового героя пока нет. Эти персонажи не добавляются в каноническую книгу героев.

Этапы открываются последовательно: предыдущие разделы формы должны быть заполнены и проверены. Следующий незаполненный этап доступен, последующие заблокированы и обозначены замком. Переход по прямому URL закрытого этапа возвращает на первый незавершённый. Пустая форма открывает только «Образ», имя открывает «Расу». Выбор класса заполняет неснижаемую основу характеристик стоимостью 10 очков. Игрок распределяет ещё 4 очка усиления: улучшает сильные стороны или компенсирует слабые. Кнопка «−» возвращает только дополнительные очки; смена класса после их распределения требует подтверждения. Пока усиления не распределены или нарушены ограничения, поздние этапы остаются заблокированными.

Правила читаются из канонических `../content/character-creation.json`, `../content/character-abilities.json` и `../content/races.json`. Раса показывает свою особенность, класс и модификаторы определяют предпросмотр HP/AC. В навыках есть базовая атака, до трёх активных профилей урона/лечения за 6 очков и до трёх описательных особенностей. Подтверждение навыков и снаряжения открывает следующие этапы; допускается оставить только базовую атаку и пустой рюкзак. Предметы не добавляют числовых эффектов.

Изображения находятся только в памяти открытой страницы через object URL. Галерея позволяет выбрать до восьми портретов PNG/JPG/WebP до 10 МБ каждый, сравнить их горизонтально, переключать и удалять варианты. Кадрирования нет; выбранное изображение показывается целиком. Иконки навыков тоже локальные. Выход очищает изображения и освобождает object URL. API хранилища и отправка готовой анкеты пока не подключены; «Создать героя» и советник отображаются недоступными с объяснением. Клиентская проверка не заменяет будущую окончательную проверку сервером.


## Навигация приложения

- `/` — карта Восьми Земель;
- `/heroes` — книга героев;
- `/characters` — все готовые персонажи конструктора;
- `/characters/<character-id>` — карточка персонажа для чтения;
- `/characters/new/<step-id>` — конструктор с формой и изображениями в памяти;
- `/races` — энциклопедия рас;
- `/region/<region-id>` — летопись выбранного региона.
- `/roadmap` — продуктовый план развития проекта.
- `/campaign/penisuela/prologue` — пролог «Мальчишника конца света»;
- `/campaign/penisuela/play/<scene-id>` — локальная игровая сцена кампании.

Маршруты управляются React Router.

## Архитектура фронтенда

Обязательные соглашения для нового кода: [CODE_STYLE.md](CODE_STYLE.md). Они определяют FSD-границы, публичные экспорты через `index.ts`, состав и размер компонентов, размещение логики и правила приёмки.

```text
src/
  app/         инициализация приложения
  pages/       карта, герои, расы, roadmap и страницы регионов
  widgets/     крупные интерфейсные блоки
  features/    навигация и игровые действия
  entities/    модели и UI героев, рас, кампаний и регионов
  shared/      конфигурация, утилиты, ассеты и глобальные стили
```

Правила проекта:

- один компонент — один файл;
- стили компонентов хранятся в `*.module.css`;
- цвета задаются только через переменные из `src/shared/styles/variables.css`;
- предметные функции и преобразования данных выносятся в модель или `lib` соответствующего слайса; `shared/lib` содержит только технические примитивы;
- интерфейс читает канонические данные из общего каталога `../content/`.

## Контент

```text
../content/
  characters.json             герои
  races.json                  расы
  rules.json                  домашняя облегчённая d20-система
  world-map.json              регионы и интерактивные полигоны карты
  campaigns/
    nor-il-skald.json         данные кампании
    nor-il-skald-guide.md     сценарий для мастера
    linda-small.json          данные кампании Вьетимы
    linda-small-guide.md      сценарий и итог кампании Вьетимы
    penisuela-session-preview.json публичные игровые сцены Пенисуэлы
    penisuela-gallery-gameplay.json исполняемые проверки, решения и встречи
    penisuela-dialogue.json   канонический банк реплик мастера
    penisuela-final-boss.json многофазный финальный босс и эпилоги
```

В приложении доступны три завершённые летописи: Нор’Иль’Скальд, Вьетима с островом Линда Смолл и Пенисуэла. Пенисуэла имеет статус `completed`; её публичная страница `/region/penisuela` рассказывает о счастливом финале: победе над Нетаком, отключении механизма и свадьбе Angel и Kreed. Под эпилогом сохранена кнопка «Начать кампанию», ведущая в пролог без сброса локального прогресса. Исполняемый bundle сохраняет обе игровые концовки и статус `ready`. Полный production-browser sweep игрового цикла ранее пропущен по явному решению автора; проверка летописи не заменяет этот отдельный sweep.

## Визуальные материалы

`assets/concepts/` содержит утверждённые портреты, карту мира, изображения регионов, референсы рас и стиль книжных листов. Индекс ассетов находится в `assets/concepts/manifest.json`.

## Локальные Codex-скиллы

- `$create-dnd-campaign` — оркестратор полного цикла новой кампании;
- сценарный конвейер — концепция, каркас, граф, NPC, сцены, реплики, механики и редакторская проверка;
- арт-конвейер — планирование, генерация, проверка и публикация утверждённых материалов;
- реализация — публикация данных, React-интерфейс, модель сессии, rules engine, поведение NPC и консоль мастера;
- `$maintain-dnd-world` и `$verify-dnd-campaign-release` — целостность канона и проверка во встроенном браузере Codex.

Общий порядок, рабочие артефакты и контрольные точки описаны в [`../docs/campaign-skill-workflow.md`](../docs/campaign-skill-workflow.md). Каждый творческий этап требует явного утверждения перед переходом к следующему.

Правила работы агентов описаны в [`../AGENTS.md`](../AGENTS.md).

## Ограничения MVP

- нет авторизации и игровых комнат;
- состояние интерактивной кампании сохраняется локально в браузере и восстанавливается после перезагрузки;
- мастер управляет страницей и показывает её игрокам через общий экран;
- новые кампании пока нельзя создавать и редактировать через интерфейс.
