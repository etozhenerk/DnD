# Тяжёлые медиа в Yandex Object Storage

Исследование после публикации тестового фронтенда, 28 сентября 2026 года.

## Текущее состояние

- `assets/concepts/` занимает 1,328 млрд байт (1,237 ГиБ); в нём 367 PNG на 685,5 МиБ, 71 MP4 на 395,7 МиБ и 30 MP3 на 166,3 МиБ.
- Изображения и медиа импортируются через `src/shared/lib/assets/resolveAsset.ts` с `import.meta.glob`. Vite копирует их в `dist/assets/` с хешированными именами. Тестовый сайт уже хранит и раздаёт эту сборку из Object Storage. Видео проверено на загрузку с `Content-Type: video/mp4` и поддержку HTTP Range.
- Локальный Git pack занимает 2,38 ГиБ. Удаление медиа из новых коммитов уменьшит текущий checkout, но не очистит историю Git.

## Что можно сделать

Object Storage совместим с S3 API. Для игры с небольшим числом пользователей подходит публичное чтение файлов из бакета, а для загрузки — сервисный аккаунт с минимальными правами. Для сайта и часто воспроизводимых роликов подходит класс `STANDARD`.

Рекомендуемый перенос:

1. Оставить `frontend/assets/concepts/manifest.json` и канонические логические пути `assets/...` в `content/` без изменений.
2. Загрузить выбранные утверждённые MP4/MP3 и крупные PNG в отдельный префикс `media/` Object Storage, сохраняя стабильные относительные пути. Не делать их зависимыми от Vite-хешей.
3. Расширить `resolveAsset`: для перенесённых путей возвращать абсолютный URL Object Storage, для остальных оставить текущий Vite import. Отдельный публичный базовый URL позволит менять домен/бакет без правки канонических JSON.
4. Проверить видео, звук, `Range`, MIME-типы и CORS для тех случаев, где браузер запрашивает ресурс с другого origin. Затем удалить перенесённые бинарные файлы из текущего дерева Git отдельным коммитом. Не переписывать историю Git без отдельного решения.
5. После переноса обновить CI: файлы из `media/` не должны повторно загружаться при каждой сборке фронтенда. CDN добавлять лишь при измеренной потребности.

Можно использовать текущий бакет, но отдельный бакет для исходных медиа удобнее: независимые права загрузки, лимиты и жизненный цикл. Это выбор этапа миграции, дополнительный бакет пока не создан.

## Оценка расходов

По [тарифу Yandex Object Storage для России](https://yandex.cloud/ru/docs/storage/pricing) стандартное хранение стоит 2,376 ₽ за ГиБ в месяц; первый 1 ГиБ, 10 000 операций записи и 100 000 операций чтения в месяц не тарифицируются. Первые 100 ГиБ исходящего интернет-трафика Object Storage в месяц также не тарифицируются. Если хранить только один экземпляр нынешних 1,237 ГиБ медиа и больше ничего, плата за место составит около **0,56 ₽/месяц** после бесплатного гигабайта. В рабочем бакете находятся также JS/CSS и другие объекты, поэтому точную сумму надо считать по общему объёму всех бакетов и фактическому трафику. Дублирование медиа в двух бакетах увеличит объём хранения примерно на 1,237 ГиБ до удаления старых копий.

Главный практический эффект переноса — уменьшение Git checkout и объёма сборки, а не экономия на хранении. Текущий GitHub Pages остаётся действующим до отдельного переключения, поэтому удаление файлов из репозитория возможно только вместе с проверенным внешним URL для обеих площадок.
